    Usar o CLI

    Exemplos dos comandos mais usados. Cada comando tem ajuda: chamados <comando> --help.

    Listar e ver

    chamados list                       # fila de suporte
chamados list --meus                # meus chamados ativos
chamados list --busca moodle --status aberto
chamados list --meus --todos --desde 2026-01-01
chamados show 559298                # detalhes, histórico e anexos

    Abrir e atender

    chamados profile update --service 53 --interested 1     # padrões, uma vez
chamados open -d "Não consigo acessar as bibliotecas virtuais" -a print.png
chamados assume 559298
chamados start 559298
chamados comment 559298 -m "Já estamos verificando."
chamados note 559298 -m "Nota só para a equipe."
chamados resolve 559298 -m "Resolvido: reiniciamos o serviço."

    Os tipos de anexo aceitos pelo SUAP são xlsx, xls, csv, docx, doc, pdf, jpg, jpeg e png (até 3 ao abrir).

    Títulos, arquivar e adiar (só seus)

    chamados title 559298 "Moodle 5.3.0"       # dá um título
chamados archive 559298                     # some das listas e do watch
chamados snooze 559298 --amanha             # volta amanhã às 8h
chamados snooze 559298 --em 3h
chamados list --adiados
chamados list --arquivados

    Escrever com IA

    Com --AI no lugar de -m, a IA escreve o texto a partir do chamado e o comando o envia. Escolha o provedor uma vez por perfil (gemini, anthropic ou openai); a chave vem de uma variável de ambiente e nunca é gravada. O conteúdo do chamado só sai da sua máquina nos comandos com --AI, e as notas internas só entram em textos internos.

    chamados profile ia --provedor gemini
chamados title 559298 --AI                              # título só a partir do chamado
chamados comment 559298 --AI "avise que sai amanhã"     # com a sua instrução
chamados resolve 559298 --AI @o-que-fiz.txt             # instrução lida de um arquivo (ou - para a entrada padrão)

    Exportar para a IA

    O comando gera um ZIP com chamado.md (texto legível), chamado.json (dados estruturados) e a pasta anexos/: ideal para entregar a um assistente de IA analisar. Nada de sessão ou cookie vai no ZIP.

    chamados export 559298
chamados export 559298 --sem-anexos -o ~/analise

    Acompanhar mudanças

    chamados watch              # avisa de chamado novo, mudança de situação e mensagens
chamados watch --suporte    # acompanha a fila de suporte

    Perfis

    chamados profile list
chamados profile init local --base-url http://localhost:8000 --username meu_usuario
chamados --profile local login

    Quando a sessão expira, o comando refaz o login sozinho e roda de novo, uma vez, se a variável SUAP_PASSWORD estiver definida e o perfil tiver o usuário salvo (chamados profile update --username <usuário>). Sem uma das duas coisas, o erro diz o que falta. A senha fica só no ambiente.

    Sincronizar entre aparelhos

    A sincronização leva seus títulos e perfis para outros aparelhos, cifrados de ponta a ponta antes de saírem da máquina. Senhas, cookies de sessão e credenciais do bucket nunca são sincronizados.

    chamados sync setup --backend directory --path ~/Nuvem/chamados   # uma pasta (Drive, Dropbox, disco de rede)
chamados sync setup --backend r2 --endpoint https://<ACCOUNT_ID>.r2.cloudflarestorage.com --bucket meu-bucket
chamados sync credentials set     # Access Key ID e Secret, guardados no chaveiro do sistema
chamados sync key generate        # gera a chave de cifra (só na primeira máquina)
chamados sync --check             # confere o destino e a chave, sem sincronizar
chamados sync                     # sincroniza (--dry-run mostra o que mudaria)
chamados sync key pair            # QR para parear o app Android (chave e bucket)
chamados sync key pair --com-credenciais   # QR que leva também as credenciais: o app configura tudo e sincroniza
chamados sync automation          # mostra o agendamento periódico (--install no systemd)

    Para incluir um perfil na sincronização, use chamados profile update --sync true (começa desligado).

    Onde ficam as informações

    Tudo isto fica só nesta máquina; a nuvem recebe apenas o documento cifrado.

    O quêOnde
    Configuração da sincronização (destino, bucket, endpoint, origem da chave, sincronização automática)seção [sync] de ~/.config/suap/config.toml (no Windows, C:\Users\<você>\.config\suap\config.toml)
    Chave de cifrapor padrão no chaveiro do sistema. Com --key-source file: ~/.config/suap/sync.key. Também pode ser protected-file (arquivo com frase-senha) ou env
    Credenciais do bucket (s3/r2)chaveiro do sistema (ou variáveis de ambiente); nunca no config.toml
    Títulos locaispasta de dados do sistema: titles.json (perfil default) ou titles-<perfil>.json
    Controle da sincronizaçãona mesma pasta de dados: sync.lock (evita duas execuções ao mesmo tempo) e removed-profiles.json (perfis removidos nesta máquina)

    A pasta de dados é %APPDATA%\suap-companion\chamados\data no Windows, ~/.local/share/chamados no Linux e ~/Library/Application Support/br.edu.ifrn.suap-companion.chamados no macOS.

    Guarde a chave. Sem ela, o que foi cifrado fica ilegível. Para levá-la a outro computador, use chamados sync key export e, no destino, chamados sync key import; o QR de sync key pair também contém a chave, então mostre-o só a quem vai lê-lo. Com --com-credenciais ele contém ainda o secret do bucket: não o fotografe nem o mostre em tela compartilhada, e use um token restrito a esse bucket.
